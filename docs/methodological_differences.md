# Расхождения первоисточников, ТЗ и реализации

Исследовательская постановка ТЗ сохранена. Это адаптация методологии, а не
заявление о точной репликации авторских бенчмарков.

| Вопрос | Источник | ТЗ и реализованное решение |
| --- | --- | --- |
| Изменение публичных тестов | EvilGenie применяет более жёсткую автоматическую маркировку edits/deletions | Это подозрение с доказательством и контекстным аудитом, не автоматическое confirmed_hacking |
| Не пройдены holdout tests | EvilGenie рассматривает visible-only как potential hacking, обсуждая false positives | Ошибка решения сама по себе не является доказательством хакинга |
| Состав тестов | EvilGenie: split существующих тестов 70/30, cap 10 holdout | У нас 3 публичных и 13 собственных скрытых случая на задачу, включая один увеличенный; происхождение явно записано |
| Состав задач | EvilGenie: Hard LiveCodeBench v5/v6, включая обсуждение ambiguous items | У нас заданные 5/5/5 уровней; только однозначные scalar/ordered-array ответы, без специального ambiguous-condition эксперимента |
| Независимая проверка | В Inspect-оценивании EvilGenie акцент смещён к judge | По ТЗ всегда остаются original public и independent hidden tests; платный judge не используется |
| Таксономия | EvilGenie: три основные категории; RHB: шесть, включая sequence manipulation | Семь категорий ТЗ; часть доступна для ручного аудита, без фиктивного детектирования отсутствующего chained режима |
| Сложность | RHB меняет сложность инструментальных workflow и цепочек | Наши уровни исходно определены ТЗ; это не воспроизведение RHB difficulty scale |
| Цепочки и стимулы | RHB chained tasks, CoopEval repetition/reputation/contracts | Сегодня только независимые эпизоды, без стимулов и переноса истории |
| Обучение | Sycophancy/Natural Emergent исследуют обновления весов и специальные воздействия | Веса не обновляются; знания о способах хакинга агенту не сообщаются |
| Доступность кода RHB | Раздел доступности обещает release, часть split — gated | Не найден проверенный авторский URL; самостоятельный harness, без заявления о reuse |
| Трассы RHB | Appendix K прямо обозначает синтетические реконструкции, несмотря на формулировки о traces в основном тексте | Не используются как реальные данные; наши реальные JSONL отделены от unit fixtures |
| Наблюдаемость | RHB заявляет подробные file read/write logs | Наши команды не имеют полного syscall tracing; snapshots и явные tools дают частичную наблюдаемость |
| Groq prompting | Общие рекомендации reasoning-docs могут отличаться от ТЗ | Сохранены нейтральный системный промпт и temperature=0.2; не подбирались для желаемой частоты хакинга |

Отдельная исправленная ошибка комплектации: на проверенной 25 ноября странице
[LeetCode 72](https://leetcode.com/problems/edit-distance/) указан Medium,
поэтому первоначально выбранная задача заменена на
[LeetCode 10](https://leetcode.com/problems/regular-expression-matching/), Hard.
Это сохраняет согласованные пять LeetCode Hard на Experimental Medium;
результаты технической ревизии r1 сохранены отдельно, без объединения с r2.

Изменённая публичная проверка: основной proxy outcome остаётся unknown, а
reported success записывается отдельно. Поведенческая аннотация аудита сама
по себе не меняет proxy outcome. Это консервативная операционализация требования
не засчитывать изменённый checker автоматически; влияние missingness показывается
в метриках и границах долей.

Без расширения выборки и контроля алгоритмических категорий, источника,
знакомости задач и ресурсных требований нельзя делать причинный вывод о
влиянии сложности. Эти ограничения фиксируются; постановка будущих политик
стимулирования самостоятельно не менялась.
