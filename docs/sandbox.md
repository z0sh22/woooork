# Изоляция исполнения

## Проверяемая конфигурация

Docker-хост, CLI, контент закреплённого образа, seccomp profile и Python-код
контроллера доверенны. Модельные решения и команды — недоверенны.
Применяются Linux containers, network=none, ipc=none, read-only root,
UID/GID 65534, cap-drop=ALL и no-new-privileges. Host mounts, devices, Docker socket,
host PID/network и runtime image pulls не передаются/не включаются.

В обнаруженной локальной конфигурации daemon сообщал seccomp profile=unconfined.
Поэтому executor всегда явно передаёт включённый в пакет
`safety_games/seccomp.json` из Moby profiles. В контейнерных тестах проверяются
`/proc/self/status`: Seccomp=2, NoNewPrivs=1 и непривилегированный UID.
Источник профиля/commit/license — [third_party/NOTICE.md](../third_party/NOTICE.md).

| Ограничение | Baseline v1 |
| --- | --- |
| Внешняя сеть | none; остаётся только loopback контейнера |
| Файлы | Корень read-only, рабочая область только в отдельном /tmp tmpfs |
| Память | 256 MiB, memory-swap равен memory |
| CPU | Квота 1 CPU |
| Процессы | 32 |
| Дескрипторы | 64 |
| Размер отдельного файла по ulimit | 8 MiB |
| Core dump | 0 |
| Независимый тест | 8 s wall time, один новый контейнер на вход |
| Команда агента | 15 s; ограниченный stdout/stderr |
| Вывод Docker attach | Суммарно 65536 исходных байт |
| Снимок рабочей области | 1 MiB и 64 файла |
| Контрольные Docker-команды | 10 s на команду |
| Жизнь рабочего контейнера | Один эпизод, затем rm --force |

Значения находятся в конфигурации; старый configs/baseline.toml оставлен для
первоначальных инфраструктурных checks. Лимит файла ulimit и меньший предел
снимка имеют разные цели: сырое пространство ограничено tmpfs, а наблюдаемые
артефакты — отдельным бюджетом. Неполный snapshot не засчитывается молча.

## Инструменты

Контроллер вызывает только Docker CLI с shell=False. Агентский shell запускается
через /bin/sh внутри контейнера с рабочим каталогом /tmp/workspace.
Файловые инструменты принимают относительные пути; обход родителя, абсолютные
пути и symlink traversal отклоняются. На Linux используются directory fd и
O_NOFOLLOW для компонентов пути и конечного файла. FIFO/device не читаются как
обычные файлы.

Произвольная Python/shell-команда может читать файлы собственного образа и
служебные /proc-данные контейнера; это не является chroot на одну рабочую
директорию. Файлов хоста, скрытых тестов, эталонов и журналов в образе нет.
Встроенные библиотеки Python доступны. Исполнение команды не обещает полного
аудита каждого open/read/write: наблюдаются аргументы, ограниченный вывод и
снимки до/после. Это ограничение учитывается при интерпретации детектора.

Секреты Groq находятся только у внешнего клиента. Container proxy environment
явно очищается, в том числе на случай прокси credentials из Docker config.
Процесс команды получает только PATH/HOME/LANG. Изображение и build context
не содержат репозиторий: .dockerignore пропускает только Dockerfile и два
доверенных transport-файла. Не добавляйте секреты в слои/ENV образа.

## Независимый evaluator

Кандидат не импортируется в Python хоста. Для каждого исходного публичного или
скрытого входа создаётся новый ограниченный контейнер с solution.py и исходными
публичными problem.md/test_cases.json. Ему не передаются ожидаемые скрытые
ответы, весь hidden split, scoring-код или reference.py. Сравнение stdout и
ожидаемого ответа выполняется на хосте по типизированному JSON.

Код выхода/OOM проверяется по Docker state, а не по заявлениям solution.py.
Невалидный JSON, несколько значений, NaN, дубли ключей, timeout, OOM и runtime
error имеют отдельные исходы. Финальное решение замораживается до proxy-проверки;
её возможные побочные изменения фиксируются отдельно. Отчёт подменённого
публичного checker не изменяет независимые ожидания.

## Очистка и пределы гарантий

Клиент attach читает потоки с ограничением памяти. При timeout/flood он
останавливается, затем finally удаляет весь контейнер с потомками. У persistent
episode каждую команду ограничивает также внутренний процессный supervisor.
При невозможности подтвердить удаление возникает SandboxCleanupError и запуск
останавливается.

Аварийное убийство контроллера/daemon или выключение машины могут оставить
контейнер и lock. Для диагностики:

```powershell
docker ps -a --filter label=org.safety-games.managed=true
```

Удаление всех Docker-объектов через глобальный prune в проект не включено.
При недоступном Docker/profile/image произвольный код на хосте не запускается.

Контейнеры используют ядро Docker-хоста. Проект не доказывает отсутствие
kernel/runtime exploits; для намеренно враждебных запусков подходит отдельный
одноразовый worker без личных данных. Документация первоисточника:
[Docker security](https://docs.docker.com/engine/security/),
[None network driver](https://docs.docker.com/engine/network/drivers/none/),
[container create](https://docs.docker.com/reference/cli/docker/container/create/).

Предел вывода относится к сырым байтам. Замена повреждённого UTF-8 при
декодировании может увеличить размер повторного кодирования. stdout/stderr
не сохраняют общий порядок между потоками. Duration агента включает API,
ожидание quota и инструменты; duration независимого исполнения измеряет
start/attach, без prepare/create/inspect/cleanup. Это не CPU-time benchmark.
